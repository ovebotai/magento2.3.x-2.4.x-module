## Installation

The module is distributed as a zip, installed in `app/code/Ovebot/Chat`. Magento 2.4 has no admin screen for
installing modules (the Web Setup Wizard of Magento 2.3 was removed in 2.4.0): the zip is copied to the server, then
the module is enabled from the command line. The same steps work on 2.3. The whole installation takes a few minutes.

### Before you start

- **SSH access** to the server, as the user that owns the Magento files - the same user that runs `bin/magento` and
  the Magento cron. Not `root`: files created by `root` cannot be changed by the website afterwards.
- **The PHP of the website.** `php -v` must show the PHP version the website runs on. If it shows another one, call
  the right binary in every command below, for example `php8.3 bin/magento ...` instead of `bin/magento ...`.
- **The Magento mode**, which decides a few commands at the end:

  ```bash
  bin/magento deploy:mode:show
  ```

- **A backup** of the database and of the files, as before any change to a live store.

All commands run from the Magento root directory: the folder that holds `app/`, `bin/`, `pub/` and `vendor/`.

### Copy the module to the server

1. **Download** `ovebot-module-chat-1.0.0.zip` from the
   [releases of the module](https://github.com/ovebotai/magento2.3.x-2.4.x-module/releases), under **Assets**. Not
   *Source code (zip)*: that archive has another folder layout and holds the development files. Do not unzip it on
   your computer.

2. **Upload the zip** to the Magento root directory on the server: with an SFTP client (FileZilla, WinSCP, ...),
   or from a terminal on your computer:

   ```bash
   scp ovebot-module-chat-1.0.0.zip user@your-server:/path/to/magento/
   ```

   Uploading one zip and unzipping it on the server is safer than uploading the folder: some clients lose files
   when they upload many at once. You can also skip this step and download the zip straight on the server, in
   step 3.

3. **Connect to the server** and go to the Magento root directory:

   ```bash
   ssh user@your-server
   cd /path/to/magento
   ```

   If you skipped step 2, download the zip here, with the link of `ovebot-module-chat-1.0.0.zip` copied from the
   release page:

   ```bash
   wget -O ovebot-module-chat-1.0.0.zip "<link of the zip>"
   ```

4. **Unzip** into `app/code`. The zip holds the folders `Ovebot/Chat`, so the module lands in
   `app/code/Ovebot/Chat`:

   ```bash
   unzip -o ovebot-module-chat-1.0.0.zip -d app/code
   ```

   `registration.php` must end up at `app/code/Ovebot/Chat/registration.php`.

5. **Check that every file arrived.** The two numbers must be equal:

   ```bash
   unzip -Z1 ovebot-module-chat-1.0.0.zip | grep -v '/$' | wc -l
   find app/code/Ovebot/Chat -type f | wc -l
   ```

   A partial copy shows up later as `Class "Ovebot\Chat\..." does not exist`. Then remove the zip:

   ```bash
   rm ovebot-module-chat-1.0.0.zip
   ```

6. **Owner and permissions.** The files need the same owner and permissions as the rest of `app/code`. Nothing to do
   if you uploaded and unzipped as the Magento file owner. Otherwise (as `root`, with your owner, group and modes):

   ```bash
   chown -R magento-owner:web-server-group app/code/Ovebot
   find app/code/Ovebot -type d -exec chmod 755 {} +
   find app/code/Ovebot -type f -exec chmod 644 {} +
   ```

7. Run the [Magento commands](#magento-commands).

If `unzip` is not installed on the server, unzip on your computer and upload the `Ovebot` folder it holds into
`app/code`, then count the files as in step 5 (the zip holds the same number as the folder on your computer).

### Magento commands

Put the store in maintenance mode, so visitors see a maintenance page instead of errors while the code is compiled:

```bash
bin/magento maintenance:enable
```

Enable the module and create its tables (`ovebot_chat_connection`, `ovebot_chat_oauth_state`,
`ovebot_chat_rate_limit`):

```bash
bin/magento module:enable Ovebot_Chat
bin/magento setup:upgrade
```

Compile the code (needed in production mode; in default and developer mode it catches a missing file right away):

```bash
bin/magento setup:di:compile
```

**Production mode only** - deploy the static files, for every language of your storefront and admin:

```bash
bin/magento setup:static-content:deploy en_US ro_RO
```

Flush the cache and open the store again:

```bash
bin/magento cache:flush
bin/magento maintenance:disable
```

### Check the installation

```bash
bin/magento module:status Ovebot_Chat
```

The command answers `Module is enabled`. In the admin panel, **Marketing > Ovebot AI > AI Chat Agent** opens the
module page and its setup wizard; see [Initial setup](#initial-setup-wizard). If the menu entry is missing, sign out
and in again, then check the role of your admin user ([Permissions](#permissions)).

On Apache with PHP-FPM, check the `Authorization` header as well: see
[Troubleshooting](#troubleshooting), "The order lookup endpoint answers 401".

The connection uses **OAuth** (authorization code with PKCE) - there are no API keys to copy and paste by hand.

## Initial setup (wizard)

The first time you open **Marketing > Ovebot AI > AI Chat Agent**, a 4-step wizard connects your store to your
Ovebot.ai account.

### Step 1 - Connect account

Click **Start Free** to create an account on the free plan, or **I already have an account** to log in. You'll be sent
to ovebot.ai to sign in, then brought straight back to the admin panel.

### Step 2 - Website pages

Pick the **CMS pages** (About Us, Shipping, Returns, Terms & Conditions, etc.) your AI agent should read and answer
from. The list holds the enabled pages of the default store view and those assigned to all store views; technical
pages such as the 404 page are not ticked by default. **Next** sends the ticked pages to your knowledge base.

### Step 3 - Products

Choose how the agent learns your catalog:

- **Use the built-in feed** - the module tells Ovebot.ai the URL of its product feed. Only products that can be
  ordered right now (in stock, or available on backorder) are included, and the wizard shows you how many items will
  be sent. The count is per variant: a configurable product is sent once for each option that can be ordered.
- **I'll provide my own feed** - keep using a compatible feed you already have (e.g. Google Merchant), configured
  directly in your Ovebot.ai account.

### Step 4 - Go live

**Finish setup** sends the feed and the order tracking settings to Ovebot.ai, switches product recommendations and
order tracking on, and the AI agent goes live on your site immediately. From here you can open the settings, chat with
the agent on your storefront, or follow the link to the agent's settings on Ovebot.ai to fine-tune it.

Connecting later to a different agent, or to a different Ovebot.ai account, starts the wizard again, since the pages
and the feed belong to the agent.

### Disconnecting

**Disconnect**, in the header of the module page, closes the connection in your Ovebot.ai account and in the store.
The feed URL and the credentials of the order endpoint that the account was given stop working at once: new ones are
made when the module page is opened next, and the account you connect to afterwards receives them. The setup, the
appearance and the switches are kept, so connecting again to the same account and agent leads straight to the
dashboard.

## Copies of the store (staging, development)

A copy of the database carries the connection of the live store with it: the same tokens, for the same Ovebot.ai
account. The module cannot tell a copy from the original. Opening the module page on the copy sends the URLs of the
**copy** to the account (the AI agent then reads the product feed and the orders of the copy), can use up the token
of the live store, which then shows as disconnected, and **Disconnect** or an uninstall on the copy closes the
connection of the live store.

**On the copy, before anyone opens the admin panel**, clear the connection in its database (add your table prefix,
if the installation uses one):

```sql
UPDATE ovebot_chat_connection
SET access_token = NULL, refresh_token = NULL, token_expires = 0, workspace = NULL,
    setup_complete = 0, chat_status = 0;
```

The copy then shows the first step of the wizard and no chat widget; connect it to a test agent or a test account
if you need the chat there. Do not click **Disconnect** on the copy instead: with the tokens still in place, that
closes the connection of the live store.

**If the copy was already opened** and the live store lost its connection or its agent reads the wrong catalog: on
the **live** store, click **Disconnect**, then connect again. The module sends the feed URL and new order endpoint
credentials of the live store to the account.

A store that really moved to another domain needs nothing: the module page sends the new URLs by itself the next
time it is opened.

## What the module exposes

All endpoints are ordinary storefront routes of the module, on the base URL of the default store view.

### Product feed

```
GET <store URL>/ovebot/feed/index/?hash=…
```

Returns the catalog as JSON. Only enabled products with a price greater than zero that can be ordered (in stock, or
available on backorder) are listed; a configurable product is listed once per orderable variant. Names, attributes,
categories, links and prices (taxes included, in the display currency) are those of the default store view.

The feed is written to `var/ovebot_chat/feed/` by the first request and served from there for the next 30 minutes,
so no cron job is needed and Ovebot.ai does not wait for a rebuild on every read. While a newer feed is being written,
other requests get the previous one; while the very first one is being written, they wait up to a minute, then get
`503` with `Retry-After`. The `hash` is the secret shown on the Settings page; a wrong
hash, or the built-in feed being switched off, returns `403 Forbidden`.

### Order lookup

```
POST <store URL>/ovebot/orders/index/
Authorization: Basic <API user>:<API password>
Content-Type: application/json
```

Request body - the order number or id, plus the customer's email or phone number:

```json
{"id": "000000123", "email": "customer@example.com"}
{"id": "123", "email": "customer@example.com"}
{"id": "000000123", "phone": "+40 7xx xxx xxx"}
```

Response:

```json
{"success": true, "data": {"id": 123, "reference": "000000123", "date": "2026-09-20 13:15:00", "status": "Complete", "total": 199.9, "currency": "RON", "carrier": "Sameday", "awb": "1ONB…", "awb_tracking_url": "https://…"}}
{"success": false, "error": "Order not found."}
```

See [Order lookup and shipment tracking](#order-lookup-and-shipment-tracking) for the rules.

### OAuth callback

```
<store URL>/ovebot/oauth/callback/
```

Used only during the wizard's **Connect account** step to complete the OAuth flow and return you to the admin panel.

## Order lookup and shipment tracking

Ovebot.ai calls the order lookup endpoint with the user and password shown on the module's Settings page (HTTP Basic).
An order is found by its number, or its internal id, together with the customer's email or phone: the last 9 digits
of the phone of the billing or shipping address. Every order of the installation is searched, up to the age set in
**Stores > Configuration > Ovebot AI > Order tracking** (60 days by default). After 10 failed authentications within
an hour, further wrong credentials from the caller's IP are turned away for an hour (`429`, `Retry-After: 3600`);
**Regenerate credentials** lifts every block. The right credentials are never blocked: behind a proxy or a CDN every
caller may reach Magento with the same IP, and the failed attempts of someone else must not stop Ovebot.ai.

The order status is the label of the store view the order was placed on, in the customer's language, and the date is
in that store view's time zone.

The tracking number is the newest one added to a shipment of the order (Magento's own shipment tracking, the
`sales_shipment_track` table). Any courier or shipping module that saves its tracking numbers there - which is what
Magento's documentation describes, whether the number is added by hand under *Ship > Add Tracking Number* or by the
module through the shipment API - works by default, with no code or setup of its own. The public
tracking page comes from a URL template, chosen by the carrier code of the tracking number, then by its title, then
by the carrier of the order's shipping method (`fancourier` in `fancourier_standard`). Templates for
Sameday, FAN Courier, Cargus, DPD, GLS, FedEx, UPS, DHL and USPS are built in; **Stores > Configuration > Ovebot AI >
Shipment tracking > Tracking URL templates** adds or replaces them, with `{code}` where the tracking number goes.

### Adding a tracking source

A courier module that keeps its tracking numbers outside Magento's shipments can add a source: a class implementing
`Ovebot\Chat\Api\TrackingFinderInterface`, declared in that module's `etc/di.xml`.

```xml
<type name="Ovebot\Chat\Model\Tracking\TrackingResolver">
    <arguments>
        <argument name="finders" xsi:type="array">
            <item name="mycourier" xsi:type="array">
                <item name="finder" xsi:type="object">Vendor\Module\Model\MyCourierFinder</item>
                <item name="label" xsi:type="string" translatable="true">My Courier</item>
                <item name="sortOrder" xsi:type="number">50</item>
            </item>
        </argument>
    </arguments>
</type>
```

The source then appears in **Tracking sources**. Sources are asked in ascending `sortOrder` (the built-in one has
10) and the first tracking number found is used. The class creates its results with
`Ovebot\Chat\Api\Data\TrackingResultInterfaceFactory`.

## Knowledge base

The CMS pages you select in the wizard are synced to Ovebot.ai as knowledge base entries with the slug
`cms-{page id}`; each entry holds the page title followed by its content converted to plain text (widgets and
variables rendered as on the storefront), plus the page URL as source. From then on:

- saving a selected CMS page in Magento resyncs its entry automatically (`cms_page_save_commit_after`);
- disabling it, removing it from the default store view or deleting it deactivates the entry on Ovebot.ai
  (`cms_page_delete_commit_after` for the deletion). That message carries the title of the page only, not its
  content; the text sent earlier stays in the entry until you edit or delete it in your Ovebot.ai account;
- pages with less than 10 characters of text are skipped, and pages beyond your plan's knowledge base limit are
  reported as skipped in the wizard.

You can still edit any entry directly on Ovebot.ai from the dashboard's **Edit on Ovebot.ai** links, and add entries
from URLs or documents in your account.

## Chat widget in the storefront

The widget is shown on every page of every store view, except the checkout, once the setup wizard is finished and
**Show the chat bubble on your site** is on. It is a small script of the module, `Ovebot_Chat::js/widget.js`, without
RequireJS or jQuery, that loads the chat of Ovebot.ai from `https://<workspace>.ovebot.ai/widget/`. The page itself
has no inline script.

- **Checkout.** The page where the payment data is typed loads no script of Ovebot.ai: the widget is left out of the
  one-page checkout (`checkout_index_index`) and of the steps of the checkout with several addresses
  (`multishipping_checkout`). The cart and the order success page keep it. A checkout extension with a page of its
  own needs the same line in its layout handle: `<referenceBlock name="ovebot.chat.widget" remove="true"/>`.
- **Full page cache.** Pages with the widget stay cacheable, with the built-in cache and with Varnish. They carry the
  cache tag `ovebot_chat_widget`; when a change reaches the storefront (chat switched on or off, appearance, setup
  finished, store disconnected or connected to another agent), the module cleans that tag, so the change is seen at
  once. As the widget is on every page, this empties the full page cache.
- **Purchases.** The order success page (`checkout_onepage_success`, and `multishipping_checkout_success` for orders
  to several addresses) reports each order to the AI agent once: its id, its grand total and its currency. The orders
  are the ones Magento names in the events `checkout_onepage_controller_success_action` and
  `multishipping_checkout_controller_success_action`. A checkout extension with its own success page is covered
  when that page uses one of these layout handles and dispatches the event, as it must for Google Analytics.
- **Preview.** **Chat with the AI agent**, in the dashboard and at the end of the wizard, opens the storefront with the
  chat already open. The link works for one hour; a link made up by someone else does not open the chat.
- **Content Security Policy.** The module allows, for the storefront only: `*.ovebot.ai` for scripts, connections,
  images and frames, `wss://*.ovebot.ai` for the chat connection, `fonts.googleapis.com` and `fonts.gstatic.com`
  for the font of the widget.
- **Themes.** The script needs no theme library: it is meant for Luma, Hyvä and any theme whose page layout keeps
  the standard `before.body.end` container. Hyvä is not verified yet.

With the minification of JavaScript on, Magento serves `widget.min.js`, created by `setup:static-content:deploy`.

## Privacy

- The module contacts Ovebot.ai only after an administrator clicks **Connect** or **Start Free** in the wizard;
  nothing is sent before that.
- Storefront visitors' browsers load the widget from Ovebot.ai; the widget's own cookies and data handling are
  described in the GDPR section above and in your Ovebot.ai account.
- The order lookup answers only when the email or phone matches the order, and only for orders within the maximum age.
- IP addresses kept for rate limiting of the order lookup endpoint are stored hashed and expire after an hour.
- The tokens of the connection and the API password are stored encrypted with the Magento encryption key.
- The module's log never contains access tokens, API credentials or personal data.

## Translations

The module pages, Stores > Configuration, the menu and the permissions come in English (`en_US`) and Romanian
(`ro_RO`), in `i18n/`. The admin panel shows them in the language of the administrator: **Account Setting >
Interface Locale**. In production mode, a language appears in that list only after its static files are deployed:

```bash
bin/magento setup:static-content:deploy ro_RO
```

The chat widget is not translated by Magento: its language is the one chosen on the Settings page (by default, the
language of the visitor's browser).

To add a language, list the texts of the module and translate the second column:

```bash
bin/magento i18n:collect-phrases -o /path/to/de_DE.csv app/code/Ovebot/Chat
```

Keep the translated file in a language package of your own (`app/i18n/<Vendor>/de_de/`), not in the module folder,
so that an update of the module does not remove it. In a copy taken straight from the Git repository, the command
also lists a few texts of the unit tests (`Test/`, not part of the release zip); they are never shown and need no
translation.

## Update

The connection, the settings and the knowledge base selection are kept: they live in the database, and an update
only replaces the files. Take a backup first, as before any change to a live store.

1. Get the new zip into the Magento root directory, as in steps 1 to 3 of
   [the installation](#copy-the-module-to-the-server), and stay connected to the server in that directory.

2. Maintenance mode on:

   ```bash
   bin/magento maintenance:enable
   ```

3. Replace the folder. It is emptied first, so that files removed in the new version do not stay behind:

   ```bash
   rm -rf app/code/Ovebot/Chat
   unzip -o ovebot-module-chat-1.1.0.zip -d app/code
   ```

   Use the name of the zip you downloaded. Run no `bin/magento` command between the `rm` and the `unzip`.

4. Check the files, remove the zip and fix the owner if needed, as in steps 5 and 6 of the installation.

5. Update the database, compile and open the store again:

   ```bash
   bin/magento setup:upgrade
   bin/magento setup:di:compile
   ```

   Production mode only:

   ```bash
   bin/magento setup:static-content:deploy en_US ro_RO
   ```

   Then:

   ```bash
   bin/magento cache:flush
   bin/magento maintenance:disable
   ```

## Uninstall

Magento 2.4 has no admin screen for removing modules: it is done from the command line, as the user that owns the
Magento files, from the Magento root directory (see [Before you start](#before-you-start)).

Uninstalling removes the connection, the settings and the order endpoint credentials of the module. The Ovebot.ai
account itself, with its knowledge base and chat history, stays. If you may install the module again later, back up
the database first.

1. **Disconnect from the admin panel.** In **Marketing > Ovebot AI > AI Chat Agent**, click **Disconnect**. This
   also closes the connection in your Ovebot.ai account; the chat leaves the storefront.

2. **Connect to the server** and go to the Magento root directory:

   ```bash
   ssh user@your-server
   cd /path/to/magento
   ```

3. **Maintenance mode on:**

   ```bash
   bin/magento maintenance:enable
   ```

4. **Disable the module and remove its tables.** The order matters: `setup:upgrade` removes the three tables of a
   disabled module only while its folder is still on the server. With the folder already deleted, the tables stay
   behind.

   ```bash
   bin/magento module:disable Ovebot_Chat
   bin/magento setup:upgrade
   ```

5. **Delete the files** of the module, the saved product feed and, if you want, the log:

   ```bash
   rm -rf app/code/Ovebot/Chat var/ovebot_chat
   rm -f var/log/ovebot_chat.log
   ```

   `app/code/Ovebot` can go too, if nothing else is left in it:

   ```bash
   rmdir app/code/Ovebot
   ```

6. **Remove the advanced options** of Stores > Configuration, if you ever saved them. In the database of the store
   (add your table prefix, if the installation uses one):

   ```sql
   DELETE FROM core_config_data WHERE path LIKE 'ovebot\_chat/%';
   ```

   For example with the MySQL client, with the database name and user from `app/etc/env.php`:

   ```bash
   mysql -u db_user -p db_name -e "DELETE FROM core_config_data WHERE path LIKE 'ovebot\_chat/%';"
   ```

7. **Let Magento forget the module**, compile and open the store again. This `setup:upgrade` removes the module from
   `app/etc/config.php`.

   ```bash
   bin/magento setup:upgrade
   bin/magento setup:di:compile
   ```

   Production mode only:

   ```bash
   bin/magento setup:static-content:deploy en_US ro_RO
   ```

   Then:

   ```bash
   bin/magento cache:flush
   bin/magento maintenance:disable
   ```

8. **Check.** Both commands print nothing:

   ```bash
   bin/magento module:status | grep Ovebot_Chat
   mysql -u db_user -p db_name -e "SHOW TABLES LIKE '%ovebot_chat%';"
   ```

If the module folder was deleted before step 4, the three tables stay behind: Magento no longer knows they belong to
a module. Close the connection from your Ovebot.ai account (the module page is gone, so step 1 cannot be done), then
remove the tables by hand, with the other leftovers (add your table prefix, if any):

```sql
DROP TABLE IF EXISTS ovebot_chat_rate_limit, ovebot_chat_oauth_state, ovebot_chat_connection;
DELETE FROM core_config_data WHERE path LIKE 'ovebot\_chat/%';
```

`bin/magento module:uninstall` is not used here: Magento runs it only for modules installed with Composer.

### Disabling is not a pause

**Disabling the module removes its data.** Magento drops the tables that no enabled module declares: with the
module disabled and its folder still in place, `setup:upgrade` removes the three module tables, and with them the
connection. To stop the chat for a while, switch off **Show the chat bubble on your site** in the Settings instead.
If you must disable the module and keep its data, back up the three tables first.

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| `Magento supports PHP 8.1.0 or later` when running `bin/magento` | The command line uses an older PHP than the website. Call the right binary, for example `php8.3 bin/magento ...` |
| `Class "Ovebot\Chat\..." does not exist` during `setup:di:compile` | Files are missing on the server. Copy the module again and compare the file list |
| Errors from factories or interceptors after an update | Generated code is out of date. Delete `generated/code/Ovebot` and run `setup:di:compile` |
| The menu entry is missing | Flush the cache, then check the role of the admin user |
| `Access denied` on the module page | The role lacks the **Ovebot AI** resource |
| The order lookup endpoint answers 401 with correct credentials | On Apache with PHP-FPM or CGI the `Authorization` header does not reach PHP. Add `SetEnvIf Authorization "(.*)" HTTP_AUTHORIZATION=$1` to the virtual host or `.htaccess`, or use `CGIPassAuth On` |
| The order lookup endpoint answers 429 | 10 failed authentications from the same IP within an hour, and the request itself came with wrong credentials (the right ones are never blocked). The block ends after an hour; **Regenerate credentials** on the Settings page lifts it at once, and Ovebot.ai receives the new credentials |
| The order lookup answers "Order not found." for an existing order | The order is older than **Maximum order age**, or the email or phone does not match the one of the order |
| The chat widget does not appear | Check that the setup wizard is finished and **Show the chat bubble on your site** is on. A page cached before the module was installed shows no widget until the cache is flushed. A theme without the `before.body.end` container needs the block `ovebot.chat.widget` placed in its layout |
| `Refused to load` / CSP messages about `ovebot.ai` in the browser console | Flush the cache so the module's CSP list is read; a policy set by another module or by the web server (a `Content-Security-Policy` header outside Magento) must allow the same sources |

The module writes its log to `var/log/ovebot_chat.log`. Tokens, passwords and customer data are never logged.

## Frequently Asked Questions

**Does Ovebot cost anything to try?**
No. The free plan is free forever and includes 100 AI replies per month, with no credit card and no time limit. Early
access: the free plan is available to the first 200 stores. Paid plans with higher limits are available anytime at
ovebot.ai.

**Do I need an Ovebot.ai account?**
Yes, but you can create one without leaving Magento. The setup wizard lets you start on the free plan directly - no
credit card, no separate signup on the website.

**How is this different from a normal live chat module?**
A normal live chat waits for you to be online. Ovebot's AI agent answers on its own - from your real product catalog
and your own pages - 24/7, and only pulls in a human when the conversation actually needs one.

**Where does the AI get its answers from?**
Only from your data: your Magento catalog, your knowledge base (CMS pages, imported URLs, uploaded documents) and
your Agent Memory. It doesn't browse the web and invent answers.

**Can the AI recommend products that are out of stock?**
No. The feed lists only products that can be ordered. When a product runs out of stock, it leaves the feed at the
next rebuild (at most 30 minutes later) and Ovebot removes it from chat search and recommendations. If it comes back
in stock, it reappears.

**Can my team take over a conversation from the AI?**
Yes, from your Ovebot.ai account. Click **Take Over** on any session, reply directly, then click **Leave** and the AI
resumes automatically.

**What happens when I hit my monthly message limit?**
The chat stays on your site and switches to contact-collection mode: visitors leave their details and every
submission lands in your Requests inbox. Only the AI's replies count toward your limit - visitor messages and your
team's manual replies are free.

**Can I try it before installing?**
Yes. Paste your website URL at [demo.ovebot.ai](https://demo.ovebot.ai) and about a minute later you'll be chatting
with an AI agent trained on your own site content. No signup required.

**Which Magento versions does it support?**
Magento Open Source and Adobe Commerce 2.3.0 to 2.4.8, tested on 2.4.8. See [Compatibility](#compatibility).

**Which couriers does order tracking support?**
Every courier or shipping module that saves its tracking numbers on the order's shipments, the standard Magento way,
works by default. Tracking links for Sameday, FAN Courier, Cargus, DPD, GLS, FedEx, UPS, DHL and USPS are built in;
others can be added in **Stores > Configuration > Ovebot AI > Shipment tracking**. A courier module that keeps its
numbers elsewhere can plug in its own tracking source.

**Does it work with several websites or store views?**
The whole installation connects as one store, with one agent. The chat widget appears on every store view; the
products, CMS pages, links and prices the agent knows are those of the default store view.

**Does it work with Varnish and the full page cache?**
Yes. Pages with the widget stay cached, and the module cleans them when a change must reach the storefront.
